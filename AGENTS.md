# DSHP collection instructions

- Keep generated Cordis overlays at the collection root: relative plugin paths resolve from the overlay file, so generating under `tmp/` breaks source loading. Replace only local placeholders and verify with a real Harness boot.
- On native Windows with Node 24, launch the Corepack `.CMD` shim through `cmd.exe /c` with verbatim arguments; direct `spawn()` fails with `EINVAL`. The accepted path is a real Harness listener and HTTP response on the configured development port.
- Before moving a plugin referenced by a DSH Profile `file:` dependency, update that manifest path while the old source still exists; `dsh plugin add` resolves existing dependencies first and otherwise fails with `ENOENT`. Regenerate the Profile lockfile and verify the installed module, real Harness listener, and plugin runtime.
- For online-provider acceptance, reject Cloudflare challenge documents before installing selection UI, and wait for required title/image metadata before normalizing a detail page; CDP readiness or a matching URL alone is not proof. Verify the first cold request returns the complete structured record.
- When an `@` source uses empty-query defaults, let the empty value reach the host service instead of applying the normal two-character client guard; give the Z-Library domain probe 15 seconds because the primary health endpoint can exceed 8 seconds. Verify from a fresh exact tarball that bare `@` shows loading and then real book records.
- When binding a DSH `SettingsScope` to React `useSyncExternalStore`, wrap `subscribe` and `getSnapshot` in closures; passing controller methods unbound loses `this` and crashes the settings slot. Verify on the real Settings → Plugins page.
- When a Pinterest consumer account cannot use Developer OAuth, reuse the normal Chrome login only through a Pinterest-scoped MV3 content script: never read or copy cookies/profile storage, pair to loopback with a short-lived random token, require a Chrome-extension Origin, and normalize only visible Pin URLs plus `pinimg.com` images. Verify a real logged-in Pinterest page, the loopback ingest gate, and native `@` cards.
- When raising a persisted numeric setting's runtime minimum, keep the Cordis schema compatible with legacy values and clamp them in the runtime resolver: schema validation runs before plugin normalization, so raising the schema minimum can make an existing Profile unbootable. Verify a real boot that still contains the legacy value and confirm the resolved behavior uses the new minimum.
- After changing a plugin manifest dependency list, regenerate its `pnpm-lock.yaml` and prove `pnpm install --frozen-lockfile` passes in a clean checkout before packaging; a cached `node_modules` directory can hide an outdated lockfile.
